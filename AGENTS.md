# KaKa — agent notes

KaKa is a **Linux-only, local-only** launcher for user-supplied Windows game
trainers. It runs a trainer `.exe` inside the Proton prefix of the game that is
currently running. Fork of [wyyadd/LaLa](https://github.com/wyyadd/LaLa)
(AGPL-3.0 — keep the license and the upstream credit). Since 2.0: Rust, GTK4 +
libadwaita (1.x was Flutter; its data formats are kept byte-compatible).

## Hard rules

- Linux only. Do not add Windows/macOS/mobile/web targets.
- Local only. No online catalogue, telemetry, update checks or network calls.
  Users add their own trainers; KaKa never downloads executables.
- Never auto-launch a trainer the user did not explicitly add.
- Start processes with `std::process::Command` and an argument list, never via a shell string.
- Keep `library.json` / `config.json`, log paths and the `KAKA_TRAINER` / `KAKA_TRAINER_ID`
  markers compatible; `crates/kaka-core/tests/fixtures/flutter/` must keep round-tripping byte-identically.

## Toolchain

- Rust pinned in `rust-toolchain.toml` (1.99.1); MSRV 1.92 (gtk4-rs).
- GTK floor 4.14 / libadwaita 1.5 (Ubuntu 24.04), enforced by the `v4_14` / `v1_5` crate
  features: newer APIs fail to compile. The maintainer host has newer GTK; CI checks the floor.
- `rustfmt` default width (100); `rustfmt.toml` only pins edition 2024.

## Verify before commit

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --release --locked -p kaka   # → target/release/kaka
```

Opt-in tests against a real Proton build (not run in CI; Wine's `cmd.exe` stands in for game and
trainer). Run both with and without the Steam Linux Runtime:

```sh
S=~/.local/share/Steam
KAKA_REAL_PROTON="$S/steamapps/common/Proton - Experimental/proton" KAKA_STEAM_ROOT="$S" \
KAKA_SLR="$S/steamapps/common/SteamLinuxRuntime_4" cargo test -p kaka-core --test real_proton -- --ignored --test-threads=1
KAKA_REAL_PROTON="$S/steamapps/common/Proton - Experimental/proton" KAKA_STEAM_ROOT="$S" KAKA_SLR= \
cargo test -p kaka-core --test real_proton -- --ignored --test-threads=1
```

Trainers start with `proton runinprefix`: `proton run` goes through Proton's `steam.exe`
helper, which did not start a second program while the game's `steam.exe` ran in the prefix
(observed with GE-Proton 11 and Proton Experimental 11, with and without the Steam Linux
Runtime, without a running Steam client; not yet checked with Steam running). `runinprefix`
worked in all of those cases. The trainer keeps an open (never written) stdin pipe for its
lifetime: console programs exit on stdin EOF.

GUI checks: there are no widget tests. Smoke-test the release build on Wayland and X11 (opens,
compositor close saves and exits 0) and walk dialogs through AT-SPI with isolated `XDG_DATA_HOME` /
`XDG_STATE_HOME`; never against the user's real data.

## Layout

| Path | Purpose |
|---|---|
| `crates/kaka-core/` | All logic, no GTK. Unit tests in each module; `tests/fake_proton.rs` (real `/proc`, fake game + recording `proton` script), `tests/real_proton.rs` (opt-in) |
| `kaka-core/src/proton.rs` | `/proc` scan, running-game detection, Proton/Steam lookup, trainer process matching |
| `kaka-core/src/launcher.rs` | `Launcher`: resolve the running game, spawn Proton, logs, startup watch, exit events, stop |
| `kaka-core/src/library.rs` | `Library` (`Send + Sync`, shared as `Arc`): library, settings, launch guard, orphan bookkeeping, shutdown. `Store` / `Backend` / `ProcessSource` traits for tests |
| `kaka-core/src/trainer_data.rs` | FLiNG "reset trainer data": only `AppData/Local/FLiNGTrainer` and the contents of `AppData/Local/Temp`; refuses while the prefix is in use or outside it |
| `kaka-core/src/game_info.rs` | Name/AppID/cover for a running game from local Steam data |
| `kaka-core/src/storage.rs`, `model.rs` | JSON in `$XDG_DATA_HOME/io.github.spaghetticodez.kaka/`, atomic writes, LaLa import |
| `crates/kaka/` | GTK4/libadwaita UI: `ui.rs` (window, cards, core ↔ UI glue), `trainer_dialog.rs`, `settings.rs`, `dialogs.rs`, `i18n.rs` |
| `crates/kaka/i18n/{en,de,zh}/kaka.ftl` | Strings (Fluent). `tr!` checks ids/args against English at compile time; a test requires the same keys in every language |
| `data/` | Desktop file, icons, default game cover (generated by `tools/default_cover.py`; edit the script, then re-render as its docstring says) |
| `docs/` | User guides (Proton, AppID, virtual desktop, dotnet) |

Blocking core calls (scan, launch, stop) never run on the UI thread: `Ui::background` uses
`gio::spawn_blocking`. Core change events reach the UI through one `async_channel`.
Running state is event-driven (Proton wrapper exit); `/proc` is polled only while trainers
left by an earlier session exist (`Library::needs_orphan_poll`).

Packaging is undecided (Arch package / AppImage candidates; no Flatpak).
